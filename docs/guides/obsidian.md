# Using Obsidian with a context

A workctx context is plain Markdown, so [Obsidian](https://obsidian.md) can
open it directly as a vault. You get visual browsing, full-text search, and
the graph view over your entities for free — while workctx remains the only
mutation path. Obsidian is entirely optional; nothing in workctx depends on
it.

## Setup

1. In Obsidian: **Open folder as vault** and select the context root (the
   directory containing `context.yaml`).
2. In the vault settings, exclude the machine-state and generated zones from
   indexing where you can, and treat them as read-only everywhere:
   - `98_state/` (locks, projections, telemetry — machine-local),
   - `99_meta/` (the audit ledger — append-only, never hand-edited),
   - `04_views/` (generated views — regenerated by `workctx view rebuild`;
     hand edits are overwritten and flagged).
3. Obsidian creates a `.obsidian/` folder in the vault root. Keep it out of
   version control if you track the context in Git (add it to the context's
   `.gitignore`); it is editor state, not canonical data.

## What works well

- **Graph view**: entities under `02_knowledge/` and tasks under `03_work/`
  link to each other; the graph shows your people/systems/tasks web.
- **Reading the brief**: pin `04_views/brief.md` and the other generated
  views as read-only dashboards; rebuild them with `workctx view rebuild`.
- **Search and backlinks**: Obsidian's search complements `workctx search`
  (which uses the SQLite full-text index and typed filters).

## The one rule

Read freely; mutate through workctx. Canonical files changed by hand bypass
validation, transactions, and the audit ledger. If you do hand-edit
something canonical, run `workctx context validate` afterwards — the
validation engine will tell you what needs repair, and `workctx index
rebuild` refreshes the projections. Evidence under `00_inbox/` and
`01_processed/` must never be edited at all: raw evidence is retained
verbatim by invariant.
