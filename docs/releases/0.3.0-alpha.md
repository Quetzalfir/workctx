# workctx 0.3.0-alpha

Release date: 2026-10-14

The third alpha is a hardening release shaped by daily use across several
real contexts. It makes agent adapters maintainable over time, teaches agents
where things belong and how to behave inside a context, and removes the
validation failures that let stray working material block canonical updates.
The workspace schema is unchanged (`schema_version: 1`); 0.2.0-alpha contexts
need no migration.

## Features

### Agent adapters you can keep current

- `workctx agent refresh --all` refreshes every registered context in one
  command: a fleet-wide preview by default, applied only with `--yes`, with a
  per-context summary and partial-failure isolation.
- Unedited packaged skills, bridges, and registries in existing contexts now
  update to the current packaged versions on install or refresh; operator
  edits are preserved and reported with exact three-way hashes so they can be
  merged deliberately. Bridges matching any historically shipped template are
  recognized as generated.
- `workctx agent forget` is the official exit from adapter trust divergence:
  it drops the machine-local trust record, and the next install re-adopts the
  exact on-disk state without touching project files.
- Contexts register themselves on use; manual `context register` is no longer
  needed.
- Context-local custom skills are first class: a `custom_skills:` registry
  section, full validation with rule-naming errors, rendering for every
  client, and no false "edited" state.

### Agents that orient, record, and know the rules

- Bridges and the bootstrap skill require agents to consult stored context —
  policies, generated views, search, integrations, declared secrets and
  connectors — before asking the operator anything, and to persist any newly
  supplied fact in the same session.
- `workctx guide` prints the placement and ownership map for a context: what
  is canonical, operator-owned, adapter-managed, generated, or machine state;
  where each kind of information goes; and what must never be hand-edited.
- Every packaged skill names the exact commands it uses, and bridges say where
  skills live so agents resolve them from the context root.
- Outbound messages are written in the operator's first person, concise and
  natural, in the language of the target conversation (detected from its
  recent messages, never from a name), falling back to the operator's
  configured default and then English.

### Validation that blocks only what it should

- A transaction no longer fails because of pre-existing errors in files it
  does not write; errors on written files and newly introduced errors still
  block, and the rest is reported as a notice.
- `working_dirs` in `context.yaml` (default `outputs`) declares non-canonical
  working areas: document checks are skipped, absolute paths are advisory,
  secret findings stay visible as warnings, and links that escape the context
  remain errors.
- Strict warning escalation applies only to the files a transaction writes.
- Possible-secret and absolute-path findings report exact line numbers and
  pattern kinds without echoing values. Operators can accept a confirmed false
  positive with `transaction apply --acknowledge-possible-secret`, bound to
  the file's exact content hash and recorded in the audit ledger.
- Proposal rejections include field-level detail from model validation.
- `workctx context refresh-meta` installs the packaged proposal schema under
  `99_meta/schemas/` in existing contexts.

### Diagnostics

- `workctx doctor` detects when machine-global state (secret names index,
  context registry, adapter trust records) is being read through a Windows
  app-container shadow copy, which previously caused silently stale results.
- `WORKCTX_SECRET_INDEX` and `WORKCTX_CONTEXT_REGISTRY` relocate that state.

## Known limitations

- Topics, activity heat, checkpoint staleness signals, and graph export are
  designed (ADR 0015) but not yet included.
- `workctx --version` is not available yet; use `uv tool list` or package
  metadata.
- The limitations listed for 0.2.0-alpha on connectors, outbox channels,
  telemetry, and UI still apply.

## Upgrade

`uv tool upgrade workctx` (or reinstall from the tag), then
`workctx agent refresh --all --yes` to bring every registered context's
adapters, skills, and bridges up to date.
